# P138-002 - Reconciliation-first phase machine and P136 two-phase outcome

## Scope

Write failing reconciliation, phase, and commit-boundary tests, then implement
the P138 coordinator over one real P136 `observe_one_cycle`, the existing
publisher, and P137 without duplicating dependency logic. Add P136's recoverable
outcome intent -> checkpoint -> completion protocol required to close both
sides of the checkpoint/P138-phase commit boundary.

## Acceptance

- P138 acquires its nonblocking lease before coordinated state reads and first
  reconciles publisher state/current bytes, P137 checkpoint/ledger, and P138
  phase/ledger.
- An unaccepted current bundle invokes only P137 against exact current bytes;
  an already accepted but unfinalized bundle validates durable P137 membership
  and finalizes without relying on replay `classification="none"`.
- Only an accepted current bundle plus finalized predecessor permits one new
  `observe_one_cycle`. Fork, gap, chain-root, state/byte, component-state, or
  predecessor mismatch fails closed without observation/publication/advance.
- Only the exact six-phase path is accepted. Empty delta uses
  `cycle_started -> p136_completed -> cycle_finalized` with zero publisher and
  P137 calls.
- Every real P136 cycle, including empty, writes
  `p136.cycle_outcome_intent.v1` after promotion durability and before
  checkpoint replacement, installs only the bound checkpoint, then replaces
  the same deterministic outcome file with `p136.cycle_completion.v1` before
  return. `cycle_started` binds the expected cycle ID, starting checkpoint,
  receipt, and outcome path.
- Same-cycle recovery accepts only intent + starting checkpoint, intent + bound
  resulting checkpoint, completion + bound resulting checkpoint, or no outcome
  + starting checkpoint. It validates bound promotion bytes (including exact
  empty), consumes no second index read/receipt, and fails closed on every
  other tuple while preserving the last valid checkpoint.
- CASE-21/22 cover checkpoint replacement before completion replacement;
  CASE-29/30 cover outcome-intent fsync before checkpoint replacement. The
  nonempty outcome publishes once, while the empty outcome finalizes no-work
  with no publisher/P137 call.
- New handoff input is exactly the contiguous promotion delta returned by that
  real cycle; later cycles never retriage earlier promotion sequences.
- Targeted P136/P138 tests, Ruff, and Mypy pass before P138-003 starts.
