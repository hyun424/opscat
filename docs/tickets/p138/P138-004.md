# P138-004 - Delta, bootstrap, authority, and leak guards

## Scope

Write failing zero-work, historical-delta, genesis-bootstrap, callable,
authority, and leak-safety tests, then enforce those boundaries in P138 and its
evaluator-only surfaces.

## Acceptance

- Finalized ledgers persist the last published promotion sequence/hash. Every
  handoff delta is exactly the contiguous new range through the resulting P136
  checkpoint; gaps, duplicates, omissions, reordering, stale records, and hash
  mismatch fail closed.
- Empty delta increments the exact no-work activity and invokes neither
  publisher nor P137.
- Bootstrap without a P138 ledger accepts only exact publisher state/current
  genesis bytes: sequence 1, null previous hash, full contiguous checkpoint
  history from 1, and matching P137 chain root/checkpoint. Partial genesis,
  non-genesis, omitted history, missing bytes, and unrelated checkpoints fail
  before observation.
- Static guards reject authentication, provider/live-connector,
  network/DNS/socket, credential/environment, subprocess/shell, signal,
  notification/delivery, action/remediation, staging/production mutation, and
  operator-replacement runtime surfaces.
- Production uses module-owned component defaults and rejects arbitrary
  callables before invocation. Fake-guard, signal, and crash injection are
  evaluator-only counters and leave the exact shared 15-key runtime authority
  tuple at integer zero.
- Promoted artifacts contain no absolute paths, secrets/tokens, endpoints, raw
  provider payloads, prompt injection, commands, delivery targets,
  action/remediation instructions, or staging/production targets.
- Targeted delta/bootstrap/authority/leak tests, Ruff, and Mypy pass before
  P138-005 starts.
