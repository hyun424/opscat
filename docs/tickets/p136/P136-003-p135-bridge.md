# P136-003 - P135 segment bridge and promotion semantics

## Scope

Build one-artifact P135 manifests from accepted entries, execute all five real
P135 adapters, and define a fully bound deterministic P136 promotion key.

## Acceptance

- P136 never parses provider segments itself.
- Equivalent duplicate/restart/rotation replay resolves from P136 promotion
  state before P135 and performs zero segment opens/reads.
- Each first-seen entry owns an independent P135 manifest and P135 receipt ledger;
  P136 stores the complete per-entry bundle and never invents a shared ledger.
- P135 authority, artifact, record, bundle, receipt, and ledger validators run.
- Success and denominator-failure promotions are distinct and tamper-evident.
- Duplicate/restart/rotation replay cannot create a second promotion or an
  unauthorized reread. The claim is promotion exactly once, not read exactly
  once.
