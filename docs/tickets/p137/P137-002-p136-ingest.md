# P137-002 - Validated P136 promotion ingest

## Scope

Implement the P136-owned sequenced fixed-path handoff publisher plus P137
handoff bundle validation, checkpoint `promotion_keys`, promotion record
`entry_hash`, embedded `promotion_key`, P134/P135 binding, canonical byte,
final-review, and exact-zero authority validation before converting promotions
into P137 evidence atoms.

## Acceptance

- P136 release status must be exactly
  `p136_incremental_local_observation_qualified`.
- Publisher genesis must use `bundle_sequence=1`,
  `previous_bundle_hash=null`, and a chain root derived from the self-hashed
  publisher genesis record. Publisher state persists that root, allocates next
  sequences, chains previous bundle hashes, binds checkpoints to bundle hashes,
  and publishes by intent, state recovery, atomic replace, file fsync, and
  parent fsync. P137 config only pins the fixed path and chain root.
- Handoff JSON byte payloads must be canonical lowercase hexadecimal exact byte
  encodings. The adapter rejects empty strings, odd length, characters outside
  `[0-9a-f]`, whitespace, prefixes, uppercase, separators,
  `bytes.fromhex`/`decoded.hex()` mismatch, hash mismatch, and descriptor length
  mismatch, and flattens decoded bytes into exact authority fields `contract`,
  `review_receipt`, `receipt_ledger`, `index_receipts`, `segment_receipts`,
  `contract_bytes`, `review_receipt_bytes`, `receipt_ledger_bytes`,
  `index_receipt_bytes`, and `segment_receipt_bytes` while preserving exact P136
  canonical JSON bytes. P137 itself strict-decodes, hash/length validates,
  JSON-parses, and exact-object-compares `segment_receipt_bytes` to
  `segment_receipts` before constructing P136 authority.
- Promotion records must satisfy
  `checkpoint.promotion_keys[promotion.entry_hash] == complete canonical
  promotion record`; implementation separately recomputes the embedded
  `promotion_key`.
- Tests cover absent checkpoint entry, altered checkpoint value, and nested
  promotion-key tamper.
- Validate every `entry_hash`, promotion key, P134 receipt, P135 bundle,
  execution receipt, and independent ledger binding.
- P137 must not require or invent a P136 promotion hash chain.
- Current P136 validators must run over the handoff bundle without provider,
  index, or segment rereads. Direct tests invoke
  `validate_incremental_observer_config(p136_config)`,
  `validate_observer_runtime_authority(p136_config, authority, now=now)` with
  only the byte fields it actually validates for contract, review, ledger, and
  index receipts plus validated `segment_receipts` mappings, and
  `validate_promotion_record(promotion, expected_entry=expected_entry,
  runtime=runtime)`. `validate_promotion_record` consumes the
  `segment_receipts` mappings; P136 is not claimed to validate segment receipt
  bytes.
- Tests cover publisher genesis, root persistence, next sequence allocation,
  previous-hash chaining, checkpoint-to-bundle binding, crash recovery,
  republication idempotency, bundle sequence rollback, same-sequence fork,
  previous-hash discontinuity, and torn fixed-path replacement.
- Successful and denominator-visible failed promotions become bounded
  `p137.evidence_atom.v1` records.
- Atom conversion is total over actual source fields: P136 `promotion.status`,
  embedded P135 record `risk_flags`, and embedded P120 `evidence_state`,
  `value`, `unit`, `state_reasons`, `labels`, `topology_refs`, and
  `deploy_config_refs`. `denominator_failure` requires P120 `fail_closed`;
  `success` plus P120 `valid` maps to `promoted_success`; `success` plus any
  other allowed P120 state maps to `context_only`.
- P120 numeric `value` accepts finite `int`/`float`, rejects bool, and maps
  nonnumeric permitted values to `null`; `numeric_unit` is the P120 `unit` only
  when `numeric_value` is nonnull. Unknown P120 `state_reasons` reject with the
  roadmap's closed `p120_state_reason_unmapped` error.
- For `promotion.status=denominator_failure`, existing P135 failure-bundle
  validation must pass. `bundle.failure_reason` must be a nonempty closed-safe
  string and exactly equal the sole P120 `state_reasons` element and the
  normalized failure label value when present. P137 maps any such
  validator-accepted P135 failure reason to
  `state_reason_codes=["local_catalog_selectable", "p135_adapter_failure"]`
  and `request_need_class=LOCAL_SELECTION`; it never enumerates or
  substring-guesses P135 failure strings.
- Absolute paths, credentials, endpoint secrets, prompt/action-shaped executable
  fields, raw provider payload leakage, or nonzero forbidden counters fail
  closed.
- Original provider artifact stat/open/read activity remains exactly zero.
