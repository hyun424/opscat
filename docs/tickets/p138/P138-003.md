# P138-003 - Publisher lease, split-commit recovery, and lock order

## Scope

Write failing publisher-contention, split-commit, phase-restart, lock-order,
loop, heartbeat, readiness, and signal tests. Then serialize the entire
P136-owned publisher operation and implement the amended recovery paths without
widening P138 authority.

## Acceptance

- The publisher's nonblocking lease is acquired before any state/intent/fixed
  read and covers candidate derivation, all writes, recovery, and cleanup.
  Conflict cannot advance sequence; every terminal path releases the lease.
- Under the lease, `(prior state, pending intent, current fixed bytes)` recovers
  all four valid tuples exactly as specified by the roadmap and rejects every
  missing, torn, forked, mismatched, or unbound tuple without deriving a new
  sequence.
- Exact evaluator-only crashes after intent fsync, fixed replacement fsync, and
  state replacement fsync before cleanup each recover the same bundle
  sequence/hash exactly once.
- Each P138 phase restart follows the exact recovery table: same cycle,
  revalidated delta, one publisher call, no republish, durable P137 membership
  finalization, or fail closed as applicable.
- Enforce only
  `P138 lease -> P136 cycle lease (released) -> publisher lease (released) -> P137 lease (released) -> P138 final ledger write`, with P138/P136/publisher/P137 contention coverage.
- The finite loop proves exact max-cycle and heartbeat/readiness cadence,
  distinct receipt-exhaustion/failure-threshold stops, stale-readiness/deadman
  behavior, and safe-boundary SIGINT/SIGTERM termination.
- Targeted P136 publisher, P137 integration, P138 recovery/loop tests, Ruff, and
  Mypy pass before P138-004 starts.
